# Stage 5: eleven potion afflictions

Implemented locally against the existing BepInEx `6.0.0-be.791+b782da4`, `net6.0` and BepInEx-generated runtime interop. **Build-only; not deployed or gameplay verified.** Stage 5 adds ten three-severity afflictions alongside unchanged Leadfoot. Surgery expansion remains Stage 6.

## Catalog and effective severity

`Afflictions/AfflictionDefinitions.cs` contains explicit keys/IDs. `AfflictionMath.cs` supplies production formulas/text; `AfflictionBattleState.cs` supplies timers, counters, per-action snapshots and delay reconciliation; `AfflictionsFeature.cs` connects native definitions, views, modifiers and events.

All effects use **native `Player.HasInjury`**, clamped to 0–3, rather than raw owned severity. Native suppression, Pain Killers and Poultice therefore affect the mechanics through the game's own decision. Raw owned severity/order remains independently stored by Foundation. Zero effective severity contributes nothing; cure/reduction/suppression also updates pending state. Leadfoot keeps ID 11010, original text/aliases, severity behavior, movement factor and optional existing offer override.

## Normal potion integration and presentation

Each new `InjuryDef` is a normal, full-game, three-level entry added before `GameLibrary.Init` builds its index. Native `InjuryGenerator` reads that library. No per-entry potion replacement postfix is installed: the generator chooses normal healing, size, model, eligibility and injury; `RunDataManager.ConsumePotionRpc` retains its native heal calculation/clamp and `PlayerData.AddInjury` bookkeeping. Native reduction, removal and cure paths remain in charge. New flags use `canBeDisabled=true`; Leadfoot's original flags are preserved.

The definitions reuse only the installed Broken Foot sprite. Native body groups are explicit: Brittle Guard uses Arms; Heavy Landing uses Legs; Shaky Resolve/Tin Ear/Obsessive Focus use Brain; Loose Change/Cold Start/Overheating use Behavioural; Lead Belly/Burning Lungs use None because this enum has no torso/lung group. These are independent identities, not donor mechanics. Original icon import is not implemented.

Owned I2 terms provide names and descriptions for severities 0–3 through the normal `StringManager` injury paths. New text uses explicit **English fallback**; the old twelve-language example aliases remain. Native cards, character information, severity skulls, long descriptions and actual language/layout behavior remain manual checks. The existing deliberately enabled Leadfoot force override can still replace an eligible potion slot; no new forced offers default on.

## Mechanics and important choices

- **Lead Belly:** a confirmed, positive native stamina spend with recovery delay enabled appends one owned delay tail to the normal timer. Repeated reads/refreshes cannot add it again. Reconciliation observes the native timer before Foundation's single Catch Your Breath recovery clock. Reducing severity subtracts only the unconsumed part of this tail; it does not remove another source's delay or start a fresh penalty. Cure/suppression cancels this exertion's pending addon; a later actual exertion may start another. Thus native delay additions apply before Catch Your Breath's clock acceleration. Shaky's resource drain uses `skipRecoverDelay=true` and cannot start another exertion penalty.
- **Brittle Guard:** `TakeHitRpc` must be in Execute stage with `CompleteBlockByShield`, positive blocked damage, an active shield and positive durability. One feedback scope publishes one block even through base/override callbacks. The extra raw loss occurs before native `NetworkAgent.OnBlock`, so its normal break, model, unequip, stun and feedback see the new durability. Zero-damage/other-nullification events and shields with no positive durability are excluded. Native ordinary wear/random exemptions are unchanged; this additional loss itself is guaranteed. Reduction clamps the partial counter to the new interval; zero effective severity clears it.
- **Shaky/Loose:** both use the existing confirmed hostile-enemy HP-loss receipt, excluding attempted/blocked zero loss and unattributed/self/environment/friendly sources. Cooldowns are independent and fixed at one/three scaled seconds, not per enemy or severity. Stamina drains are capped by current stamina and use the native owner path; gold loss uses native `ModifyMoney`. Existing equipment/skill loss subscribers run before these penalties, so Locket's restoration precedes Shaky's drain on the same receipt. No new physical coin pickups are spawned.
- **Tin Ear:** native `PlayerCrowdData.ProcessBattleEvent` separates local weighted excitement and combo gains from raw damage/variety/tempo scores, excitement pools and timing. Only positive gains in `localCrowdExcitement` and `currentCombo` caused by that player's event are scaled. Accumulated favor is never rescaled; decay, raw scores, pool depletion/recharge, fixed combo duration and explicit external ForceWild calls remain native. The native crowd meter/state reads the resulting values. Nested processing is guarded so a contribution is not reduced twice. Check the live crowd presentation manually.
- **Burning Lungs:** a new default-neutral `RegenerationAmount` channel scopes native `UpdateStamina` → `RestoreStamina` grants. It covers both regular and haste regeneration. It does not also multiply the base recovery-rate getter, and it excludes one-time grants outside that update and nested grants. Movement uses actual horizontal velocity, with the same small stationary tolerance used by the earlier skill/Chalk code. Equipment/skills can still restore their full one-time amount.
- **Heavy Landing:** a real transition into `StartDash` arms one completion; `OnDashComplete` spends it once and starts the fixed 0.75-second window. No dash parameters, inputs, native results or stamina costs are replaced. The Heavy Landing modifier is neutral during `IsDashing`; Leadfoot/other independent movement contributions remain. Reduced effective severity changes the active penalty; zero clears it without rearming on a later read.
- **Cold Start:** real battle-start scope establishes age. Acquiring it after ten elapsed seconds does not create another ten-second window. Damage reads are fresh contributions. Restore preserves elapsed battle age; scene/UI refreshes do not restart it.
- **Obsessive Focus:** the first target calculation for an attributed action freezes its prior focus/expiry. Every target of that action is evaluated against the same prior focus, including mapped projectile area calculations, before any result can change it. Only positive **direct** hostile HP loss establishes/refreshes focus. Among successful targets of one action, the lowest pre-hit native target order selects the next focus, independent of callback order. Target token/order are captured before death/despawn. Area/generated damage may receive an applicable outgoing penalty but cannot establish a new direct focus. Each qualifying direct result refreshes the fixed three-second duration. Cure/suppression invalidates pending action snapshots. Unmapped calculations use current focus without inventing a last-attack identity.
- **Overheating:** real deduplicated melee commits establish stacks **before payment**: costs are normal, then +one, +two, +three stacks. Further attempts remain at three. The two-second boundary is inclusive for reset; a ranged attempt breaks the consecutive-melee chain. The native melee-payment scope multiplies otherwise-normal positive stamina costs once per native payment, including native special-melee subpayments, without incrementing stacks on payment/property reads. Other drains/dodges/throws are outside that scope. Cure/suppression invalidates cached heat through an epoch so removing/reacquiring cannot revive an old pending cost.

Target-aware `NativeStatContext` retains its original two-argument constructor and adds target/attributed-action context. Scoped projectile attribution is separate from direct contact: area/generated results do not become direct-hit rewards. Existing Payback's flat addition stays after outgoing percentage contributions. Original modifier-channel values remain stable; the new regeneration channel is appended.

## Persistence, resets and rollback

Raw severity/order uses Foundation's existing independent external records and one-time Leadfoot legacy import. `terms-and-contusions:afflictions/battle-v1` stores schema 1 battle age, damage cooldown remaining times, landing duration, focus token/duration, block count, heat stacks and attack age. Captures clone bounded values; validation rejects unsupported/malformed state before native restore. Restoration never drains stamina, removes gold, adds injury, replays a block/dodge or grants a resource.

Native player/run checkpoints do not contain complete arena objects or the player's live stamina/recovery timer. Existing same-process focus tokens can remain valid; an unavailable target on restore is explicitly cleared and logged, rather than inventing a different target or penalizing every new spawn. Lead Belly's live timer tail is removed on reset/restore and is not reapplied to a reconstructed native timer; the next genuine exertion starts its correct active contribution. This is not a full arena/stamina snapshot. Timers that are meaningful independently store remaining scaled gameplay seconds, not offline/process timestamps.

Battle/run reset clears counters and transient state. Actual effective-severity changes are read on relevant callbacks/modifiers and the guarded runtime tick; canonical ownership/equipment changes also refresh pending state. Native `RemoveAllInjuries` bypasses individual removal callbacks, so Foundation snapshots registered owned afflictions and uses its existing transition gate to publish only real bulk-removal changes, excluding no-ops/nested duplicates/failures/restoration. Pending state therefore clears immediately, even before a same-frame reacquisition, without replaying acquisition callbacks. Cooldowns remain bounded across severity changes; zero severity cannot trigger their effects. A saved battle key and elapsed age prevent a scene/UI callback from starting a new Cold Start period.

Pre-change checkpoint: `backups/expansion-stage5-20261025-185657`, outside loader scan paths. It preserves all Stage 4 source/docs/tests/scripts/examples/build artifacts, installed v0.7.3, configuration, user data and SHA-256 inventory. Nothing is deployed or migrated. Future rollback must restore the compatible DLLs/configuration and entire matching user data, including native SaveData and `ModFoundation/checkpoints`, as one set. Downgrading only a DLL against a checkpoint owning new afflictions is unsupported and can block restoration. See [persistence](../foundation/PERSISTENCE.md) and [migration](../foundation/CONFIGURATION_MIGRATION.md).

## Manual test after final authorized deployment

1. Generate/drink normal potions for all eleven afflictions at one/two/three skulls. Check names, descriptions, native model/skull UI, expected healing/clamp, costs/selection bookkeeping, severity cap and independent ownership/order. Water and unrelated potions must retain native behavior.
2. Use normal cure/reduction, native suppression, Pain Killers and Poultice. Verify effective severity zero is neutral, reduced effects update immediately, partial block/heat/focus/landing state follows the rules, and no later read replays a penalty. Include preserved Leadfoot and a full/bulk cure.
3. Measure Lead Belly after actual exertion, skip-delay drains, repeated UI reads and another spend. Reduce/cure midway through normal/own delay. Combine Catch Your Breath and a native extra-delay weapon; verify one composed delay, not repeated multiplication or a changed recovery rate.
4. Count Brittle blocks at fourth/third/second boundaries with ordinary and one-durability shields, native wear exemptions and shield breaks. Armor nullification, zero damage, duplicate feedback and scene refresh must not add false counts. Verify normal break visuals/unequip.
5. Take actual enemy damage around Shaky's one-second and Loose Change's three-second boundaries, from multiple enemies, with little stamina/gold and a lethal hit. Blocked/self/environment/friendly damage must not trigger these penalties. Check Locket + Shaky ordering and the next hit's live Purse/Expensive Taste values after gold loss.
6. Compare Tin Ear's identical action contributions at all severities, native combo/favor meter progression and decay. Compare moving versus stationary regular/haste regeneration with Burning Lungs, plus unchanged one-time Locket/Waste Not restores. Do not infer success solely from tooltip numbers.
7. Dodge and measure Heavy Landing only after completion for 0.75 seconds; repeat/cancel dodges, reduce/cure while pending and combine Leadfoot. Measure Cold Start just before/at ten seconds, acquire it late and refresh UI/scenes without restarting the timer.
8. Focus one enemy, hit the same/different enemy, miss/block, hit several targets in one action and use a delayed/area projectile. All targets in one action must use the same prior focus; only confirmed direct hits update it. Check three-second expiry, death/despawn, cure/reacquire and unavailable-target restoration.
9. Commit consecutive melee attempts, including misses, flail/special/multi-hit paths and zero-cost/native-free actions. Check normal/one/two/three-stack costs, fixed cap and two-second idle boundary before payment. Ranged attempts break the chain; property reads, repeated payment callbacks and other resource drains do not add stacks. Cure/reacquire before a delayed payment must not revive old stacks.
10. Restore the same and older paired checkpoints with pending timers/counters, then start a fresh battle/run with the same seed. Verify no gold/stamina/injury replay, correct elapsed/remaining time, explicit unavailable-focus cleanup and no repeated native hook/receipt/save errors. Live stamina, recovery timer and vanished arena instances are not serialized by the native checkpoint.
