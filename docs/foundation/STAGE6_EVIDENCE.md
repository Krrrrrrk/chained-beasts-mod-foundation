## Public API additions

- `SurgeryServices.Register(key, price, Func<Surgery> factory, forceOffer=false)` and `IsOwned(PlayerData,key)`. Claim identities first. One provider per key; factory must return its claimed ID and configured quote. Providers from separate plugins share the same adapter and disabled claims are ignored. Never copy a private native save slot or install another replace-slot postfix.
- Appended `StatChannel.MaximumStamina`, `DodgeDistance`, `IncomingKnockback`, `HealingAmount`; existing numeric values and context constructors are preserved. Existing `RegisterModifier` automatically gates disabled identities and composes factors.
- `AttackRecord.IsUnarmed`, `CombatServices.IsSpecialMeleePayment`, `CurrentDirectAttack`, `OutgoingKnockbackMultiplier`, `FindLiveTarget(token)` and `DealGeneratedDamage(source,target,amount)`. The latter uses the native solo/server-authoritative path and a generated scope. An ordered native HP-dispatch ledger also separates generated/unrelated receipts from pending direct bonuses/executions on the same route. Target tokens are the existing independent spawn identity, not serialized pointers.
- `CombatServices.RestoreStaminaGrant(player,amount)` clamps a one-time native restoration and excludes it from passive-regeneration modifiers, including when called from a nested regeneration context.
- Shared completion receipt, eligibility and combined-pool sampling are actual pure production logic in `Logic/SurgeryTransactions.cs`, linked by the nongame checks.

Feature state capture remains fail-closed. An unfinished custom surgery or unresolved Counterweight contact cannot publish a checkpoint without its corresponding ownership/effect state. No transition, tick damage, healing, stamina grant, purchase or live native handler is invoked by restore/validation or nongame tests.
