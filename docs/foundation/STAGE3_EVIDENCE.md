Investigation uses the installed generated wrappers plus native ISIL/disassembly in ignored `analysis/phase5/isil/IsilDump/Assembly-CSharp`; additional wrapper reads are ignored under `analysis/expansion-stage3`. The numbered coroutine class/field identities are version-specific **and were checked against the installed interop**. A game update requires reinspection/rebuild, not guessed offsets. Runtime resolution uses exact parameter types; nongame checks inspect metadata without loading Unity. All declared weapon Attack/AttackEffect wrappers are discovered from the installed Weapon type hierarchy; this avoids pretending a base detour covers an override that never calls it.

Normal held-weapon/object throws are the supported range/charge path. Bow firing, offhand abilities, grappled/thrown enemies and separately generated/trap launches are different paths. No additional C# range clamp was found after the standard launch values; actual physics limits, collisions, special-object deviations, randomized angles, targeting and animation timing remain manual verification. Nominal ballistic proofs do not establish live scene distance or hit behavior.
