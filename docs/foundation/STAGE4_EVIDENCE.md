# Stage 4 native evidence and shared additions

The inspected game is unchanged: GameAssembly SHA-256 `72f2892607b0772470caae5db766dc07aaf636c3edfe26cefe019a5b9ddae56b`. Installed BepInEx-generated runtime wrappers provide exact signatures; native ISIL in ignored `analysis/phase5/isil/IsilDump/Assembly-CSharp` establishes the implementation paths below. Additional wrapper inspection and raw builds/checks remain ignored in `analysis/expansion-stage4`. Inspection stubs are neither runtime references nor proof of native method bodies.

| Observed implementation | Shared adapter choice |
|---|---|
| `Player.CompleteExecution(Enemy,ExecutionDef,PickupType)` constructs an execution event and calls `NetworkHealthObject.TakeDamage` with execution handling; a null result produces a native error path | Scope that dispatch, then confirm positive HP loss and death in `TakeDamageRpc` Execute. `ConfirmExecutionRPC` instead begins the execution coroutine/animation and is insufficient |
| `Weapon.AttackEffect` and direct projectile processing call `Player.ModifyAttackDamage` with native `isBackstab`; a later `TakeDamageRpc` changes HP | Capture the decision in the existing exact scoped attack/target; expose it with the later confirmed direct-hit receipt |
| Death may despawn an enemy while damage is still unwinding; `Enemy.OnNetworkSpawn` and `NetworkAgent.OnNetworkDespawn` expose native lifecycle | Generate an independent target token per spawn, deduplicate repeated spawn notifications and capture it on the hit before death; don't mint a different reward identity on resolution |
| `RunDataManager.ModifyMoney` clamps negative results to zero, records positive earnings and invokes the money-change callback | Use it for actual Ledger payment/Mitts grants; verify a 5-gold payment delta, clamp positive grants against integer overflow and track no second payment on re-equipping |
| `NetworkHealthObject.HealRpc` uses the native health update/feedback; `Player.RestoreStamina` uses owner handling and clamps to its normal maximum | Use these resource paths after confirmed events; pre-clamp healing to attainable health, preserve native feedback and later healing modifiers |
| `Weapon.LoseDurability` modifies raw/special durability, computes effective display durability, invokes UI and destroys genuinely exhausted weapons; Leather Gloves may randomly exempt ordinary loss | Extra cost uses that path after contact, with a tightly scoped exemption bypass only for the promised additional cost; native break/Waste Not observation remains shared |
| `Pickup.RequestPickupRpc` checks pickup eligibility, calls `NetworkAgent.ReceivePickupRpc` and destroys the pickup; `Player.ReceivePickup` constructs a new `PickupData`, can drop the old weapon, then equips the received object | Explicit incoming/outgoing transfer scopes preserve physical identity and publish recovery only after successful native equipment assignment |
| `Player.EquipWeapon` calls base equipment assignment and refreshes durability; the same model can be reused with different `PickupData` | Key the physical item separately from the model/wrapper; verify the actual assigned data before recovery/repair |
| `Pickup.SetDataRpc`, `Projectile.ToPickup`, `PickupManager.SpawnPickup` reconstruct data; normal projectile landing/trigger/embed paths create pickups. `CreatedEmbeddedPickupRpc` also calls `SpawnPickup` | Carry explicit weapon GUIDs through the existing launch provenance/generation and scoped representation transfers; never identify all equal type/origin values as one weapon |
| `Player.IsAimingThrow` checks actual attack mode/state; `PlayerData.PlayerObject` logs an error when no runtime players exist | Chalk samples native aim/velocity; guard the runtime player manager/count before polling. Stop preparation outside the allowed Solo context |
| Native `PlayerData.Checkpoint` stores character/HP/skills/injuries/history; run checkpoint stores run/progression state, without arena weapon/projectile/enemy instances | Save independent paid/spent/timed equipment feature records; do not claim complete arena reconstruction or serialize process pointers. Native-created resume objects are new physical instances |

New reusable APIs: `AttackRecord.Weapon`, `DirectHit.TargetId`, `IsBackstab`, `FlatDamageBonus` / `MultiplyDamage`, `CombatServices.ExecutionConfirmed`, `WeaponRecovered` and `ConsumeOpeningDurability`, plus `FoundationServices.GameplayTick`. Existing Stage 3 events/formulas remain. GameplayTick itself may run outside Solo so consumers can clear preparation; consumers must gate game mutations using actual session authority.

`Logic/{DamageComposition,RepresentationTransfer,SpawnTokenMap}.cs` are pure production helpers used by both adapters and nongame checks. Physical GUIDs/reward tokens are independent identifiers; native pointers/network IDs are transient lookup/generation evidence, never persisted as content identity. Equipment paid/spent state is in the pack, not Foundation.

All adapters are **runtime unverified**. Builds and metadata checks verify compilation and installed signatures, not Harmony interception, Netcode scheduling, UI, actual resource behavior or physical transfer.
