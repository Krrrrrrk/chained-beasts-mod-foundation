# Stage 2 adapter evidence and limits

Investigation is read-only native disassembly/ISIL plus the actual installed BepInEx-generated interop metadata. Recovered Cpp2IL C# declarations were not used as runtime bodies or references. Local generated investigation output remains under ignored `analysis/`; game binaries and dumps are not redistributed.

GameAssembly SHA-256: `72f2892607b0772470caae5db766dc07aaf636c3edfe26cefe019a5b9ddae56b`. Runtime references remain BepInEx `6.0.0-be.791+b782da4`, Unity `6000.3.21f1`, `net6.0`.

| Native evidence inspected | Adapter decision |
|---|---|
| `PlayerData.CreateCheckpoint()` loops `Enum.GetValues`, populating enum-sized level/order arrays; `RestoreCheckpoint(Checkpoint)` rebuilds dictionaries and assigns saved HP directly | Do not index arrays with custom numeric IDs; assign external skill/affliction dictionaries after native restore, without resource replay |
| `PlayerData.AddSkill(SkillType,int)`, `RemoveSkill(SkillType,int)`, `AddInjury(InjuryType,int)`, `RemoveInjury(InjuryType,int)` mutate actual ranks/severity | Canonical before/after ownership events with signed-count bounds and reentrancy protection; no permanent processed-level ledger |
| `RunDataManager.AddPlayerSkillRPC(int,SkillType)` reaches `PlayerData.AddSkill` then the data-change delegate, without a later custom HP write; `RemoveSkillRpc(int,SkillType,int)` reaches canonical RemoveSkill | Observe the actual dictionary transition rather than both outbound and executing RPC wrappers; update Bulk Up HP before native data-change notification |
| `NetworkSession.CreateCheckpoint(bool,bool)` creates native run/tutorial checkpoints, assigns the mode-specific persistent checkpoint, calls Save, then syncs | Capture a snapshot at run checkpoint creation; match it to the exact platform-save payload |
| `PersistentData.Save()` serializes via native Newtonsoft.Json and UTF8, calls platform `WriteFile("SaveData",...,CurrentSku)`, then OnDataChanged/private-data write; it does not await SaveData's task | A Save postfix cannot prove disk success |
| `Platforms.Steam.WriteFile(string,byte[],IPlatform.Sku)` and Standalone counterpart return native Task; their async state machines await `File.WriteAllBytesAsync(Path.Combine(Application.persistentDataPath, PlatformFileUtility.SkuFileName(...)))` before SetResult; exceptions reach SetException | Prepare sidecar before dispatch, observe the returned task, commit only on success. DEFAULT SKU maps to unmodified `SaveData`; pending recovery verifies that exact disk file |
| `NetworkSession.RestoreCheckpoint()` precedes RestoreCheckpointRpc, which reaches `RunDataManager.RestoreCheckpoint(Checkpoint)` and each player's restore | Early restore preflight plus run-level context; direct matching saved-player preview is handled separately |
| `PlayerData.OnCheckpointSynced(Checkpoint,bool)` verifies native values; `Checkpoint.Validate()` handles native arrays | Temporarily hide metadata in both paths; sync itself does not grant content or replay resources |
| `RunDataManager.Reset()`, `StartNewRunRpc(int,int,AscensionLevel,DifficultyConfig,int)`, and `NetworkSession.ClearCheckpoint()` | Clear transient state on reset/explicit clear; seed plus native start time identifies a fresh run |
| `GameLevel.OnStateChanged(int)` with `eSceneState.RUNNING=4`; native completed-level counter | Minimal battle scope keyed by run/completed level; repeated callbacks and restored same scope do not rearm it. Enemy/weapon/combat provenance is later work |
| `Player.ReceiveEquipmentRPC(PurchaseType)` and live current-equipment field | Emit equipment change only when before/after equipment actually differs |
| PlayerData.MaxHealth, Player.FinalMovementSpeed, StaminaCostDash, StaminaRecoveryRate; Player.HasInjury applies native suppression/reduction | One shared fresh-baseline modifier pipeline; Leadfoot uses effective severity, never raw severity for its speed effect |
| `GameManager.CurrentGameMode`, native `clientList.clients`, `IsLocalClient`, manager authority and player count | Developer mutations/forced offers require actual Solo mode, one local client, one player and host authority; leaving that state/reset clears overrides |
| `RunDataManager.GetTrainingSkills(int)` returns a new temporary list; acquisition and later reveal request separate copies | Preserve the confirmed v0.7.3 backing-row fix for forced Bulk Up: both `trainingSkills[layer][slot]` and the returned list contain the same ID. No new native UI detour/scanner |

`scripts/test-stage2.ps1` verifies installed metadata for the 30 new core hook targets (declaring type/name/arity), and native enum vacancy for all four preserved IDs plus example SkillType 12000, without loading those assemblies. Runtime resolution still uses exact parameter types via `FeaturePatcher.RequireMethod`. The I2 Get/TryGetTranslation parameter names and signature were independently checked in installed generated code. The native Task.FromException API used to preserve the prior file on preparation failure was likewise checked.

These observations justify patch selection; they are not runtime evidence that the new callbacks or save adapter execute correctly. In particular, actual serializer round trips, asynchronous hook interception, preview/restore ordering, canonical skill-removal paths, HUD updates, dependency startup and missing-content refusal remain for manual gameplay testing after final authorized deployment.

Adrenal Graft retains its old generator substitution and executing-RPC/money-delta completion heuristic, including zero cost. Stage 6 must replace it with confirmed completion and shared surgery offers. Surgery rerolls remain a known deferred issue. The Stage 2 API does not claim to expose damage provenance, bleed, throw charging, per-enemy allowances, or all future content events.
