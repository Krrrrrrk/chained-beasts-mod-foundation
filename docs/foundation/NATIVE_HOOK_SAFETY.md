# Native hook safety: crash investigations

The user also crashed in 0.8.1 after acquiring Pick Your Moment. The prior flood was absent. [The 0.8.2 investigation](../CRASH_2026-10-26_SECOND.md) records another hazard: WeaponCharge.Attack and WeaponAxeCharge.Attack share RVA `0x7c44d0` and delegate to the unique Weapon.Attack. The override loop now leaves both wrappers native and observes that base call instead. NativeHookPolicy refuses these known wrappers; NativeEntryClaims additionally rejects different wrappers sharing a native entry in FeaturePatcher, while allowing multiple patches on the same wrapper. The pointer comes from the installed Il2CppInterop helper and inspected Unity 6 MethodInfo layout. This guard covers this helper, not direct patches from other plugins. Sole crash causation and 0.8.2 runtime success remain unproven.

## Earlier no-op detour and missing visuals

The user's first 0.8.0 gameplay crash produced **77,673** `NullReferenceException` entries from `DMD<Projectile::OnDespawn>` / the IL2CPP native-to-managed trampoline, beginning immediately after chainloader startup. Local native inspection of the unchanged game build shows `Projectile.OnDespawn()` consists of a single **ret** instruction. Such folded no-op native bodies can share an address with unrelated methods. A managed wrapper's existence and parameter count cannot establish that a detour is safe.

An offline audit of the installed GameAssembly code-generation method table confirms OnDespawn at RVA `0x6005a0` is shared by **433 managed method slots**. OnDestroy at RVA `0x764710` occurs in one slot and has a substantial native body. No game process was initialized for this audit.

0.8.1 removes that detour. It uses the inspected nontrivial `Projectile.OnDestroy()` for destruction cleanup; pooled launches already invalidate attribution through `LaunchGeneration`, a new Launch replaces the cached mapping, and battle/run reset clears it. Native originals remain in charge. `FeaturePatcher.Patch` now checks the actual production `NativeHookPolicy` and refuses the known unsafe target before installing any detour. This is a specific known-target guard, **not** a universal native-code scanner or guarantee that other uninspected methods are safe.

The same log separately showed all eleven new skills disabled because the preferred ThrowCharge/StrengthTraining icon wasn't available. Their factory now prefers a valid requested native sprite and otherwise uses another valid native skill sprite, without copying its identity/effects. An unavailable preferred donor must not silently prevent the entire skill catalog from registering. The selector is pure production logic covered by nongame regression checks; actual native registration still requires a fresh startup log.

The screenshot's `0xc0000005` error confirms a crash, but no native dump/WER stack was located during this investigation. The unsafe detour and registration failures are confirmed defects and are fixed in code; the **sole cause of the hard crash is not proven**. Do not call 0.8.1 runtime verified until the user repeats the Solo test. No loader upgrade, binary/asset/save edit, automatic game launch or gameplay simulation is part of the fix. Full local evidence and the exact hotfix backup/hashes are linked from [the crash report](../CRASH_2026-10-26.md).
